# تک‌نما — مجله فناوری و Blog CMS چندنویسنده‌ای

یک پروژه فرانت‌اند کامل و نمونه‌کارمحور برای یک مجله فناوری فارسی که وب‌سایت عمومی و پنل مدیریت محتوا را در یک کدبیس ارائه می‌کند. تک‌نما با Next.js، React، TypeScript و Tailwind CSS ساخته شده و از ابتدا برای رابط راست‌به‌چپ، محتوای فارسی، دسترس‌پذیری و تجربه کاربری واکنش‌گرا طراحی شده است.

> این پروژه از صفر تا صد با همکاری ChatGPT شکل گرفته است؛ از ایده‌پردازی، معماری صفحات و طراحی UI/UX تا پیاده‌سازی، بازبینی کد، رفع خطا و نوشتن تست‌ها.

## معرفی پروژه

تک‌نما دو تجربه مستقل اما هماهنگ دارد:

- وب‌سایت عمومی مجله برای مطالعه مقاله‌ها، جستجو، مرور دسته‌بندی‌ها، برچسب‌ها و پروفایل نویسندگان
- پنل تحریریه برای مدیریت مقاله‌ها، نویسندگان، رسانه‌ها، دسته‌بندی‌ها، برچسب‌ها، دیدگاه‌ها، آمار و تنظیمات

هدف پروژه نمایش توانایی طراحی و توسعه یک رابط واقعی در مقیاس CMS است؛ نه صرفاً مجموعه‌ای از صفحه‌های جدا از هم. مسیرها، حالت‌های خالی و خطا، فیلترها، فرم‌ها، نمایش موبایل، metadata و کنترل‌های کیفیت نیز در پروژه در نظر گرفته شده‌اند.

## قابلیت‌های اصلی

### وب‌سایت عمومی

- صفحه اصلی با ساختار مجله‌ای، پرونده روز، موضوعات داغ و مطالب منتخب
- آرشیو مقاله‌ها با جستجو، فیلتر دسته‌بندی، مرتب‌سازی و صفحه‌بندی
- ذخیره وضعیت فیلترها و صفحه‌بندی در URL برای اشتراک‌گذاری و عملکرد صحیح Back/Forward
- صفحه جزئیات مقاله با فهرست مطالب، زمان مطالعه، اشتراک‌گذاری، نویسنده و مطالب مرتبط
- صفحه عمومی دسته‌بندی‌ها، نویسندگان و برچسب‌ها
- صفحه جستجو و حالت‌های بدون نتیجه، خطا و 404
- فرم خبرنامه و دیدگاه با اعتبارسنجی و توضیح شفاف درباره نمایشی‌بودن ذخیره‌سازی
- طراحی کاملاً Responsive و RTL

### پنل مدیریت

- داشبورد تحریریه و نمایش شاخص‌های اصلی
- مدیریت و ایجاد مقاله با ویرایشگر TipTap
- مدیریت نویسندگان و پروفایل‌ها
- مدیریت دسته‌بندی‌ها و برچسب‌ها
- کتابخانه رسانه و جریان آپلود نمایشی
- مدیریت و بررسی دیدگاه‌ها
- داشبورد آمار و تحلیل محتوا
- صفحه تنظیمات چندبخشی
- فضای مسیر مستقل زیر `/admin`

### کیفیت رابط و تجربه کاربری

- فونت متغیر Vazirmatn به‌صورت self-hosted
- طراحی واکنش‌گرا برای موبایل، تبلت و دسکتاپ
- Skip Link و پشتیبانی بهتر از ناوبری با کیبورد
- Focus Trap و بازگرداندن Focus در دیالوگ‌های جستجو و منوی موبایل
- کنترل‌های لمسی با ابعاد مناسب
- پشتیبانی از `prefers-reduced-motion` و حالت کنتراست بیشتر
- بهینه‌سازی تصویر اصلی و رندر بخش‌های پایین صفحه
- metadata پویا، sitemap، robots و Web App Manifest

## اجرای پروژه

پیش‌نیاز: Node.js نسخه `20.9` یا جدیدتر.

```bash
npm install
npm run dev
```

پس از اجرا:

- وب‌سایت عمومی: `http://localhost:3000`
- پنل تحریریه: `http://localhost:3000/admin/dashboard`

مسیرهای قدیمی پنل مانند `/dashboard` و `/posts` برای سازگاری به ساختار جدید هدایت می‌شوند.

## دستورات پروژه

```bash
# اجرای محیط توسعه
npm run dev

# بررسی ESLint
npm run lint

# بررسی TypeScript
npm run typecheck

# اجرای تست‌های کیفیت
npm test

# ساخت نسخه Production
npm run build

# اجرای نسخه Production
npm start

# بررسی HTTP مسیرهای اصلی؛ پس از اجرای سرور
npm run test:smoke
```

برای اجرای Smoke Test روی آدرس متفاوت می‌توان متغیر `SMOKE_BASE_URL` را تنظیم کرد.

## ساختار پروژه

```text
app/
├── admin/                 # مسیرهای پنل تحریریه
├── articles/              # آرشیو و جزئیات مقاله
├── authors/               # فهرست و پروفایل نویسندگان
├── categories/            # فهرست و صفحات دسته‌بندی
├── tags/                  # فهرست و صفحات برچسب
├── search/                # جستجوی عمومی
├── layout.tsx             # پوسته و metadata اصلی
├── sitemap.ts             # نقشه سایت
├── robots.ts              # سیاست ایندکس مسیرها
└── manifest.ts            # تنظیمات Web App Manifest

components/
├── public/                # اجزای وب‌سایت عمومی
├── layout/                # پوسته پنل مدیریت
├── editor/                # ویرایشگر مقاله
└── ...                    # ماژول‌های نویسنده، رسانه، دیدگاه و آمار

lib/                       # داده‌های mock، typeها و serviceها
public/                    # فونت، تصاویر و دارایی‌های ثابت
scripts/smoke-test.mjs     # تست HTTP مسیرهای مهم
tests/                     # تست‌های خودکار کیفیت رابط و معماری مسیرها
```

## وضعیت فعلی داده‌ها

این نسخه یک Frontend Prototype کامل است و داده‌های آن از فایل‌ها و سرویس‌های mock خوانده می‌شوند. قابلیت‌هایی مانند موارد زیر هنوز به Backend واقعی متصل نیستند:

- احراز هویت و سطح دسترسی کاربران
- ذخیره دائمی مقاله‌ها و تنظیمات
- آپلود واقعی فایل و فضای ذخیره‌سازی رسانه
- ثبت و مدیریت سمت سرور دیدگاه‌ها
- عضویت واقعی در خبرنامه
- آمار زنده کاربران و محتوا

رابط کاربری در بخش‌هایی که ذخیره‌سازی واقعی ندارند این محدودیت را به‌صورت شفاف اعلام می‌کند.
